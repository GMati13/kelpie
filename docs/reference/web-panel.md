# The Web panel

A browser per profile, and kittyfix.py, the proxy fixing Herdr's kitty graphics bugs.

## Web panel

Web panel (the globe, `cmd-shift-s`; `main.js`): a browser per profile. The panel has slots `web`, `web-1`…`web-3`, each a block showing the core terminal of that name (Herdr keeps a slot whose terminal hasn't started, but `hc kill` or `hc rm` of a shown slot's terminal makes it rewrite the layout file, stripped of its settings, without the block and with the panel column folded: never end a shown one; restore from git, then `layout.resize panel-body weight 1`, as the folded column's width sticks as its height). A profile takes a free slot the first time it opens Web (shared `kelpie.web`'s `slots`, a deleted profile's slot freed), and keeps it. A slot's terminal runs `/bin/sh -c 'while :; do <reset keyboard mode, delete images>; clear; <browser>; sleep 2; done' sh <kittyfix path> <start page>` (`browserCommand()`: both reach the script as `"$1"`, `"$2"`, never written into it; nothing typed: typing into the user's shell broke under zsh-vi-mode once a killed browser left its keyboard mode on); a slot holding anything else is replaced once, after the panel switches to another child.

The browser runs `terminal-browser` with the tab and address bars, behind kittyfix.py (skipped without python3), on the profile's start page (`web.home`, the profile dialog's Web section; empty: terminal-browser's last page, else blank). terminal-browser runs every window in one background process with one cookie folder and one last-page store, so each profile's gets its own: `XDG_RUNTIME_DIR`, `TERMINAL_BROWSER_APPDATA` and `XDG_DATA_HOME` under `~/.local/share/kelpie/web/<profile id>/`, private (0700 from `web/` down: made under `umask 077` in a subshell, so the browser's own files keep the usual mode, and an older folder tightened, `browserCommand()`). No terminal-browser installed: a toast says so instead of opening the panel. terminal-browser rescales the page on any terminal size change (another display, a resized window or panel): the footer polls the shown slot's size with `hc get` every 3 s (mods aren't told sizes) and sends `ctrl+0` once it changes (`watchBrowserSize()`).

While the profile's browser shows, a ⋯ menu beside the globe offers Restart browser (ends its kittyfix and Electron processes, matched by its folder but never the loop's shell, forgets the page it would reopen, as a stuck page would freeze it again; the loop starts it again) and Sign out of all sites (careful: also deletes its `data` folder); `resetBrowser()` in main.js. Each profile keeps whether the panel is open and what it shows (`kelpie.web`'s `panels`), saved and restored on a profile switch by `syncPanel()` in the footer, which also never lets a profile show another's slot; a saved child the layout no longer has shows nothing. While a profile's browser plays sound for `PLAYING_AFTER` (10 s, so a notification's ping doesn't count) and isn't on screen, its globe in the tab bar turns into three moving bars (`soundBars()` in ui.js, tip "… · Playing sound"; music with the browser hidden, say): the footer's 3 s timer runs `watchPlaying()`, which, while a slot's terminal is live (no browser running, nothing is asked: it ran for everyone, every 3 s), reads macOS's "Playing audio" power assertions (`pmset -g assertions`, Chromium holds one while it plays, with how long) and the playing process's environment (`ps eww`, no shell) for its profile's folder (`kelpie/web/<id>/`), and notes the folders in shared `kelpie.web.playing`, written only when they change; no pmset (not macOS): nothing shows.

The demo's comes from its fixture's `web.playing` (off by default)

## kittyfix.py

The web panel runs behind `mods/kelpie/kittyfix.py` (it never stops on bad input: a chunked image given up or never finished (no chunk for `CUR_FOR`, counted from its last chunk: counted from its first, a 2.5 MB frame read slowly was dropped while still coming) is dropped, as it used to hold back all output and froze the browser; frames already finished go out at once while the next one's image is still coming (they waited for it: 126 frames, 64 MB, were once held); `scripts/bench-kittyfix.py` measures its CPU and memory on frames shaped like terminal-browser's (`a=T,f=32,o=z` with X/Y, chunked) through a real pty (about 45 ms of CPU a 2.5 MB video frame, half of it system time: a macOS pty gives 1 KB a read, and reading more per pass didn't lower it), a padded patch costs ~4x a whole frame a byte, and a resize costs one whole frame; an unterminated command past `HOLD_MAX` passes through; a parse error passes the bytes on; a command split across reads, even between its terminator's ESC and backslash, is held from its own start, as taking that ESC for a new sequence once broke a frame and froze the picture; and it never blocks: writes go through queues on non-blocking descriptors and Herdr's input is always read, as a blocking write to Herdr once deadlocked both and froze the browser until it was killed; when Herdr is slow, the browser's output waits unread past `OUT_MAX`; text split across reads is joined, so the cursor move placing an image is always found; a held command isn't rescanned while a read has no ESC; terminal-browser draws its first frames before it knows the cell size (16x34 px cells in Herdr's 10x26: a page wider than the panel, whose pieces made the artifacts) and takes the real one only on a resize, and Herdr can answer its question late (~15 s after a restart, still working through the old browser's frames): the proxy answers it at once from the size Herdr last gave (`Cells`, kept in `~/.cache/kelpie/kittyfix-cell`), drops Herdr's same answer when it comes, and when there's none yet or Herdr's differs (a zoom) gives it the pixel size Herdr leaves at 0 and a one-column resize put back after `NUDGE_FOR`, `child_size()`; every image goes out under a fresh id (`FRESH`): an id sent again with a new picture showed its old one for a moment, on top (old video frames flicking in), and the image it replaces, or one the browser deletes, goes at the next frame's end or after `RETIRE_FOR`, once its successor is drawn; while logging (`--log`), each frame is followed by a numbered kitty query whose answer times how far behind Herdr is, with how long the browser took to write the frame and paused before it, `Probes`: during video Herdr kept up within 0.11 s and the browser wrote a 1 MB frame in 0.04 s, then paused ~0.15 s, its own capture rate, about 5 fps whatever `render.fps` says), a PTY proxy fixing Herdr's kitty graphics bugs: Herdr ignores placement `X=`/`Y=` offsets and draws columns 10.083px apart while reporting 10px (zoom 1.2), so terminal-browser's patches land off (stale tiles); and a delete before the new image makes Full frames blink.

The proxy pads images into place from column 1 and drops or defers deletes inside each synchronized block. It needs `terminal-browser config set render.presenter patched` once per machine (setting lives outside the repo). `--log FILE` prints counts. Resizing still lags (each size change is a full frame). Don't stream frames into a mod's `image()`: Herdr never frees them (leaked ~160 GB)
