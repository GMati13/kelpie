# The Changes view

Each pull request's files and a story's uncommitted and unpushed work, the file list, the diff and its keys, and what keeps a big diff within a render.

## Changes

Changes: each PR's files (`gh api …/pulls/<n>/files`) and uncommitted work per repo (`changes.py`, reads `.git/HEAD`, ~0.1 s for 229 repos): every repo in a ticket folder (a folder named exactly after a key, one or two levels under the profile folder, e.g. `<root>/worktrees/KEY/<repo>`, any branch), plus repos at the root or right under it whose branch names the key; with `--committed`, each repo's branch also says what it committed since it left the default branch (`origin/HEAD`, else `origin/main`/`origin/master`, else a local `main`/`master`; none on that branch itself or a detached HEAD), shown as a group of its own between the uncommitted work and the pull requests, "no PR yet" (`changeGroups()`, #13), unless a pull request of the story is on that branch in that repo (`headRefName`, asked in every search and kept in the shared copy) or has that very commit at its head; its hidden lines are read from `git show HEAD:<path>`, not the working tree.

The Changes view's file list and diff scroll on their own (the diff both ways: a `v_virtual_list` inside an `overflow_x_scrollbar` box as wide as the longest line, as Herdr's own Changes mod does; every box down to them needs a definite height, `h_full`/`flex_1` + `min_h(0)`). The file list opens with the review's progress ("5 of 11 viewed" and a bar), headings per repo or PR (its repo, `not committed`, `no PR yet` or `merged`, the key only when it isn't the story's, viewed n/m; the full label is the tip) and per file a status letter (`fileStatus()`: GitHub's status or the local patch's mode lines; A green, D red, R accent, M dim; the tip says it and a rename's old path), generated files muted; its foot shows the keys.

Keys, once the list or the diff was clicked (`filesFocus`, `diffFocus`, one `keys()` handler): n/p the next/previous run of changed lines with 3 lines above (`stepChange()`, `view.changes`; going on from the last jump until a wheel scroll, else from the page's top), ]/[ the next/previous file, v ticks the file shown, ↑/↓ files in the list. The diff is drawn GitHub's way (`diffRows()` in stories.js, parsed once per patch): old and new line numbers and a +/− column in a tinted gutter, the line without its prefix, the words that changed inside a paired removed/added line marked stronger (`wordChanges()`, a token LCS; skipped when the lines share under 40%), light syntax colours by extension (`syntaxSpans()`: comments, strings, numbers, keywords; prose and unknown files plain), bands between hunks naming the function they're in, whose buttons open the hidden lines (`fileRows()`: ↓ 20 more under the code above, ↑ 20 more over the code below, Show all, Show the rest of the file after the last hunk; the file's text is read on the first press: the working tree for local changes, the PR's blob by its `sha` for PRs, `openGap()`, kept in `DIFF.text` by file and version).

All files (default) puts every file on one page, each pull request (or repo with uncommitted work) under a section heading (`section()`: icon, repo and number large, its title (a branch's commits: the branch), Open/Merged/Not committed/No pull request yet, files viewed, an accent rule; a click opens the PR), each file under a header row (a Viewed box at a fixed x, `VIEW_X`, hit-tested like the bands: ticking folds the file and puts its header at the top, unticking unfolds it; a tick taken off by hand isn't put back by scrolling or showing, `this.unticked`; New file / Deleted / Renamed from … after the name; why it's folded; a click elsewhere folds; lockfiles, minified, snapshots and files over 1500 changed lines start folded, `FOLD_FILES`); bands are 26px, ruled above and below; the file at the top as it scrolls is the one shown and lit in the list (`track()`, run from the list's wheel handler), a file counts as viewed once its last row was on screen, and clicking one in the list scrolls to it (`VirtualListScrollHandle`); One file shows one at a time (its own scroll handle, put back to the top on each file).

Each story keeps its own place in both and in the file list (`diffScrolls`, below under Scroll positions). Herdr's virtual lists refuse handlers inside the row renderer (`on_click` throws) and `cx.notify()` from it: clicks go through the list's one `on_item_click(key)`, the band's buttons are fixed widths hit-tested against the press position (`bandHit()`), and the renderer only records its range (it's first called with every item, before the list knows its height, so past `DRAW_FIRST` lines it gets blank boxes of the right height). The list takes at most 10 000 items ("item_sizes may contain at most 10000 entries"), so a run of code lines is one item of up to `CHUNK` lines, a heading, file header or band one each, and a run of changed lines starts an item 3 lines above it, where n/p scroll (`view.changes` are those items; `starts`/`ends` and the viewed tracking count items too).

The mod engine is far slower than V8 and Herdr interrupts a render that runs too long ("This view could not be re-rendered … interrupted"): work over whole patches (`patchHash()`, `fileStatus()`, `diffRows()`) is cached per patch (every patch of the story shown, up to `DIFFS_KEEP` characters, the oldest going first), never redone per frame, and a render spends at most `PARSE_FOR` ms parsing, marking and hashing patches (marking what changed inside each pair of lines, `markWords()`, is the slow part: one file of long changed lines took longer than a render and was cut off every time, so it's done a removed line at a time and goes on where it stopped): what's left waits for the next render, which `cx.timer.after` asks for, the view saying "Reading the changes: n of m files…" meanwhile (a 140-file pull request parsed in one render got cut off, and as only 8 patches stayed parsed, every render after it started over and was cut off too).

A timer, not a task: a task spawned in a render with no `await` before its end runs inside that render, where `cx.notify()` is refused, so the view never redrew; the header shows the path (folder dim), +/− and GitHub's five squares (`changeSquares()`). changes.py reports a renamed file under its new path (numstat's `{a => b}`) and sends an untracked file's content as an all-added diff. No bar above the diff: both modes are one list, One file just holding one file, every file under the same header (a flat band ruled above and below, like the rest of the layout: no cards or side frames; the chevron only in All files), which holds the Viewed box, Copy path, Open on GitHub (Show in Finder for uncommitted files) and Ask Claude at fixed places hit-tested by press position (`headActs()`/`headHit()`, as the bands' buttons are: the press comes as drawn, zoom included, so its x is divided by the zoom from a 100-wide probe, `diff-zoom-probe`; a press just beside an action, between the Viewed box and the first or just past the last, does nothing, so a click on an action never folds the file); Ask Claude points the story's Ask line (in its details, below) at the file, lit while it does, laying nothing over the diff; a pull request's file goes as its pull request's rebuilt page and its path only when that's plain characters (`checkedPath()`), never the repo's name as GitHub gave it (KELPIE-302).

The All files / One file switch sits under the progress line at the top of the file list. The file list and the diff are an `h_resizable` (`changes-split`): the list starts 260 wide and drags between 180 and 640, Herdr keeping the width under the group's id (the same for every story); its progress bar is a percentage, so it follows the width. A Changes reload that fails keeps the last data under a notice. Empty states of a story not started yet (`begun()`: no space, agent, session or PR) don't talk about agents.
