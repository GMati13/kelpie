# The demo

The demo profile, its fixture, its stand-in agents, and how to take screenshots of it.

## Demo

Demo (`demo.js`, `mods/kelpie/demo/`): `herdr-app do kelpie.demo` makes the profile `demo` ("Acme") and opens the fixture's spaces; edit `demo/demo.json` and press Refresh to change what it shows (times are relative, "-25m"; a pull request's `later`, `{after: seconds, checks…}`, takes its place that long after `kelpie.demo` ran (shared `kelpie.demo.at`, cleared by `kelpie.demo-remove`; unset in the tests, so the fixture is as written): web#423's checks turn green 20 s in, to watch a change reach the list; a pull request's `opens`, `{after, found}`, doesn't exist until `after` seconds in and the search finds it only `found` seconds in (`demoNewestPulls()` has it at once; unset, it never opens): search#236 opens 15 s in and is searchable at 120 s, to watch the quick read find a pull request an agent just opened; the profile name, keys and Changes come from it; a `solo: true` in its profile (unset in the fixture: a team's board) makes the board one worked alone, read when `kelpie.demo` makes the profile; its searches then answer every issue of the fixture: Jira's sprint search with no assignee clause, the Project's `…All` queries).

Its links can't reach anyone: Jira at `jira.example.com` (a domain reserved for examples), GitHub as `kelpie--demo` (GitHub allows no double hyphen in a name), never a real account. `herdr-app do kelpie.demo-remove` (`removeDemo()`) undoes it: closes the profile's spaces, deletes it and its entries in shared state, and removes its folder only when that's inside `~/.local/share/kelpie/demo` (never its `herdr-app`, the demo window's home). The profile's `demo` flag, and the same flag on its `jira` and `github` sections (what the loaders see), make `jira()` (sprint.js, through the same checks as jira.sh's answers), `searchPulls()` (`{ demo }`), PR files and blobs, `changes.py`, `sessions.py`, Start review's checkout, What next? (`demoSuggest()`, a few seconds of brewing) and the footer's limits (`demoAccounts()`) answer from the fixture, as does GitHub's limit (`demoLimit()`: fixture `github.limit`, `"used"` or `"low"`, off by default, starting `github.after` seconds (20) after `kelpie.demo` ran, so the stories load first, and resetting `github.resets` after it: used up, a Project demo's load fails as a refused one does and a Jira demo's keeps its pull requests; either way the freshness line says so, as under Pull requests); transitions are kept in memory until the mod reloads. `herdr-app do kelpie.demo-github` turns the same profile's board into a GitHub Project of the same issues (`setupDemo("project")`, `demoBoard()`: a `project` section and no `jira`; `kelpie.demo` puts Jira back; one profile, as two would open spaces of the same names): `demoProject()` answers project.js's queries by operation name from the fixture's `project` (`{title, repo, iteration}`): issue #175 of `kelpie--demo/acme` is ACME-175, each board column a Status option `opt-<n>` named as it (an issue's the column holding `MOVED[key] ?? status`), the fixture's sprint the current iteration; a fixture pull request's `closes` is its closing link (web#412, merged and naming no key, so the Jira demo doesn't show it).

Its agents are `demo/agent.sh <state> <session name> [line…]`: it reports itself to Herdr as Claude (OSC 7501 `state=…:app=claude-code`, `kind=permission` when blocked), sets the terminal title and draws the lines (ANSI as `\033`); a message sent to it plays a short turn; a tab's `work` (`{prompt, edits: [{path, at}]}`, paths under the profile's folder) is what the plugin's find_agents says it started on and changed (two agents, ACME-172's and the Desk's, changed `web/src/theme/tokens.ts` in the same folder). A demo profile's new agents (`claudeArgv()`) and its sessions (ids `demo-…`, `resumeArgv()`) start the stand-in, never Claude; it keeps no session file, so Pause gives each demo agent a `demo-paused-…` id of its own (`sessionOf()` in stories.js).

The profile dialog keeps the flags and asks no sign-in for it. For screenshots, run it in a second Herdr window with its own home (`HERDR_APP_HOME=<folder> <Herdr binary>`, then `./install.sh` with the same `HERDR_APP_HOME`), so your own profiles stay out; spaces still live in herdr-core, shared by both windows, so close the demo's afterwards. A window only redraws while on screen, and `herdr-app shot` has no macOS window buttons: `screencapture -o -l<window id>` does, at the display's scale (shoot at Herdr's default zoom 1, where `traffic_lights` [24, 15] centres them on the profile row; Herdr places them in points, unzoomed)
