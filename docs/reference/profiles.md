# Profiles

What a profile holds, the profile dialog, Let me configure it for you, agents' changes and the yes-dialog, sending to agents, and what a space belongs to. The configure-profile skill (`plugin/skills/configure-profile/`) must stay in step with every setting here.

## Profiles

Profiles (`config.js`, shared `kelpie.profiles` by id): name, folder, Jira `{url, site, board, keychain, tokenCommand, email, prompt, orchestrator, handover, solo, moveToDone, byPriority, showPriority, unassigned, hoursPerDay}` (`orchestrator`: optional prompt; set, or with the plugin on the profile's account (#246), the story offers Start orchestrator; prompts fill `{subtasks}`, a subtask's key a line, KELPIE-302), or instead a GitHub Project `project {url, owner, ownerType, number, prefixes, prompt, orchestrator, handover, solo, moveToDone, byPriority, showPriority, priorityField, unassigned, hoursPerDay}` (`solo`, `moveToDone`, `byPriority`, `showPriority` and `unassigned`: true/false only, saved at once like `handover`, as is `priorityField`; `unassigned`, "Show unassigned work" under the Board page's Your part, off by default, `showsUnassigned()`: the list's Unassigned section, below under Stories; `solo` also makes every ticket in scope the person's, under Stories below; priority below under Stories; `hoursPerDay`: a number of hours, more than 0 and at most 24, saved at once too, the Board page's Hours a day, default 6, `DEFAULT_HOURS`) (one board or the other: `buildProfile()` refuses both, "set one to null"; owner, `ownerType` user/org and `number` (an integer, like `jira.board`) come from `url` by `parseProject()`, as Jira's site and board from `parseBoard()`; `prefixes` checked by `parsePrefixes()`, its message after `project.prefixes: `; read as the github section's `account`, no sign-in of its own), GitHub `{owner, account, reviewPrompt, storyReviewPrompt, mergePrompt, approvalPrompt}` (`account`: optional, the GitHub account Kelpie acts as for it, below under Pull requests; `reviewPrompt`: optional, the person's own words for the review agent's first message, `reviewTask()` in config.js, unset `/kelpie:review`; `storyReviewPrompt` the same for a story's pull requests reviewed together, `storyReviewTask()`, placeholders `STORY_REVIEW_FIELDS`; `mergePrompt` and `approvalPrompt` the same for Merge and Request approval (`approvalTask()`, `mergeTask()`, placeholders `MERGE_FIELDS`); every job's prompt unset is its skill line, below under the Claude Code plugin), `prompts {fix, comments, merge, post, approve, changes, idea, picked, explain, check, fixit, test, suggest, configure, triage}` (optional: the person's own words for what PR and review buttons send to agents, `ASK_PROMPTS` (ids and labels; only `picked` and `triage` have Kelpie's wording) and `askText()` in config.js, `{prs}` the links; `idea`, `picked`, `suggest` and `configure` are What next?'s and Let me configure it for you's, below; `explain`, `check`, `fixit`, `test`, `left` Ask Claude's suggestions (`ASK_CLAUDE`, below); the dialog's Messages page; every prompt the layout sends is a profile setting, keep it that way), `skills {ticket}` (#244: how a purpose is done, pinned: `kelpie`, Kelpie's own routine, or one of the person's skills by its slash name, `SKILL_PIN`, as it goes into the message as it is; unset is automatic; only the purposes the plugin's dispatcher knows, `PURPOSES`; the Prompts page's Use for tickets, Automatic / Kelpie's own / A skill of yours, with a line at the page's top when the plugin isn't on the profile's account (`hasPlugin()`, asked once as the dialog opens); a pinned ticket's message is `/kelpie:ticket <key> <link>` and `use: <pin>`, over the ticket prompt and whether or not the plugin was seen, then what follows it (a pick's words, `OTHERS`): `dispatchText()` reads `pinOf()` by skill name; the orchestrator keeps its own), `claude {config}` (see Claude accounts below), `attention {triage, model}` (finding agents that wait on you, below under Agents waiting in silence: `triage` true/false, on unless false, "Find agents waiting on you" on the Agents page, and `model`, both saved at once), `commands {leftovers, cleanUp, status}` (optional shell commands run in the profile folder with `{key}`, `runCommand()` in config.js with a timeout, refusing a key that isn't a ticket key before anything runs, as `{key}` goes in as it is: leftovers check, run once per key of a finished story (its own and its subtasks', `storyKeys()`, as work is often done under a subtask's key), 10 s each, every 2 minutes, prints what that key left behind (nothing: clean); clean-up (saved as `wrapUp` before, still read) by a finished story's broom, once for each key the check found something under (`kelpie.clean.leftovers` keeps each story's lines by key, `leftoversByKey()`), 25 s each; its confirm dialog lists the lines (Confirm's `items`, `leftoverItems()`), a subtask's key beside its lines. What a line says is the profile command's (the guide asks for readable lines); the mod only tidies it (`readable()`: paths under the profile's folder relative, the home folder as ~, runs of spaces as one); status, 4 s, its first line shown dim in the story body while the story has a space, every 3 minutes and on Refresh, kept by profile and key (`STATUSES`, as two profiles' boards may share a key); Ask Claude beside each of them sets it up through Let me configure it for you, below).

The profile dialog (`setup.js`) opens as the whole window with no frame (`openProfile()`: an overlay is only px or a share of the window, neither alone fits a laptop and stays comfortable on a big screen) and draws its own card in the middle (dimming the window around it, as Herdr dims nothing behind a frameless dialog), at most 820×900 and the window less 24 on each side (`FIT`), so on a 1440×900 screen, zoomed too, the page and the side tabs scroll and Save and Cancel stay on screen; it shows one page at a time under side tabs (`TABS`: General (name, folder); Connections: Board (tab id `jira`, so `kelpie.edit-profile-jira` still opens it; `board` and `project` open it too, `project` on the Project's form unless the profile has Jira: a choice of Jira or GitHub Project, `boardKind`, Save keeping only the one chosen; Jira's form as before; a Project's address with Check, `checkProject()` → `project-check.js`: read as the GitHub page's account through `gh()`, two constant queries `KelpieCheckUser`/`KelpieCheckOrg` with the owner and number as variables, the Status options, an iteration field, the repos, and the token's scopes from `gh api -i user`'s `X-OAuth-Scopes` (`project` moves, `read:project` only reads, no header can't be told), a missing scope offered as a gh command to copy (`scopeCommand()`: a named account is switched to and back to the account gh has active, asked then by `gh api user`, as `gh auth refresh` acts on the active one); then each repo's key prefix as an input (`prefixList()`: its own, `defaultPrefix()`, unless typed; only other ones saved, as `prefixes`; invalid or shared ones stop Save), the handover choice from the Status options; its tab line "GitHub · <title>"; the demo's answered from the fixture), GitHub, Web; Agents: Agents (the accounts agents run on, a section per kind of agent, as more may come: Claude's account, with a guide to adding another: its own folder, the footer's limits line, the plugin, a shell function's `CLAUDE_ACCOUNT_CHOSEN`), Prompts, Messages, Story commands), each tab's second line saying what's set (`tabStatus()`); props `focus` picks the tab (`herdr-app do kelpie.edit-profile[-<tab>]` opens the shown profile's), a failed check (Save's too) shows its tab and dots it.

Save builds the profile in `draft()`; anything differing from the draft at open is "Unsaved changes", and Esc/Cancel then need a second press, as Delete profile (at the end of the General page, away from Save) always does (`careful()`). Prompts saved under the board (`jira` or `project`, with its handover column, whichever is chosen) or `github` are kept only while that connection is set (the page says so). Let me configure it for you (a quiet button at the start of the dialog's Save row: everything; Set up with Claude on each page; Ask Claude on a group or field: sign-in, Claude account, handover, leftovers, clean-up, status) starts a new Claude on the profile's Desk (`configureOnDesk()` in config.js, tab `Configure[ <scope>]`), or, while the Desk has Claudes open, each button is a menu (`menuButton()` hosted on the dialog's `menus`, as `armed` is taken): New agent, or the message sent to one of the Desk's Claudes (`hc send`; ones waiting for an answer aren't offered), saving the dialog's changes (a new profile too) and closing it first.

It needs the Kelpie plugin on the profile's Claude account (`hasPlugin()`: its `plugins/installed_plugins.json` lists `kelpie@kelpie` and its `settings.json` doesn't turn it off; the demo needs none); without, a confirm dialog says so (`askPlugin()`), listing the commands to copy on that account (`CLAUDE_CONFIG_DIR=<its folder> claude …`, plain `claude` for Default, as a plain one installs on `~/.claude`), whose Install it runs `claude plugin marketplace add <the clone the mod runs from>` and `claude plugin install kelpie@kelpie` in a Desk terminal on that account (a failed install says so there, under Claude's own message; `installPlugin()`, called by the dialog's own button, like `applyPendingProfile()`, as installing adds a program Claude runs).

Its first message is `/kelpie:configure <id>` and `scope: <scope>` with the plugin (#246, the plugin's `configure` skill, whose routine is `configure-profile`), unless the profile saved `prompts.configure` (the person's own, else `/kelpie:configure <id>` and `scope:`, `configureText()`, placeholders `{name} {id} {scope} {about} {home}`, scopes `CONFIGURE_SCOPES`); the plugin's `configure-profile` skill is the agents' guide to every setting (what, why, how to find and check it, secrets never through the agent): keep it in step with any profile setting added or changed (`tests/js/skills.test.mjs` checks it against config.js: what waits for a yes, what's saved at once, scopes, messages, placeholders).

On scope `all` (whose `{about}` says prompts are included) and `prompts`/`messages`, it goes through the agents' prompts with the person (#55, #246): it says each job goes as its Kelpie skill (their own skill for it, else Kelpie's routine) and asks only whether a job should go another way, pinning a skill they always use or saving their own words for it, nothing else. The agent saves with the plugin's `save_profile` tool, which writes `<home>/kelpie/profile-apply.json` (`{id, set}`) and runs `herdr-app do kelpie.apply-profile` (`applyProfileRequest()`: known keys only, each section's own (`SECTION_KEYS`, so `github.pat` is refused though `SECRET` misses it), sections merged, a null key or section removed, strings only (but integers for `jira.board`/`project.number`, true/false for `notify`, `attention.triage`, `solo`, `moveToDone`, a number of hours for `hoursPerDay`), secret-like keys refused, the dialog's checks), which writes `profile-apply.result.json` and removes the request.

A request touching what can run commands, steer agents or move the Jira sign-in (`CONFIRM_KEYS`: commands, prompts, skills, claude, web, the jira sign-in, address and prompts, the project's address (owner, kind, number), key prefixes (keys go into `{key}` commands and folder names) and prompts, the github account and prompts; a board's `handover` applies at once) isn't saved: it waits in shared `kelpie.profile.pending` (30 minutes) behind a confirm dialog listing it (`needsYes()`: each setting under its page and name as the profile dialog has them, "Prompts · Merge", `SETTING_NAMES`, over its whole value as lines, a command in monospace, a prompt in the reading font; a changed value as lines removed and added, `lineDiff()` in dialogs.js, worked out once per dialog; new or removed said beside the name, a prompt unset standing for its default; the opening line says why by what changes, `whyItWaits()`; the dialog is the whole window with no frame, its card sized to what it says up to the window less `CHANGE_FIT.margin`, only the changes scrolling: Herdr's scroll area takes no height from what it holds, so the changes measure themselves and that, divided by the zoom, is its height, `changesHeight()`; Herdr's elements have `when()` and `map()` but no `when_else()` or `when_some()`, which the test stub refuses too), and only that dialog's own button saves it (`applyPendingProfile()`, called from dialogs.js, never a command an agent could run); the result says `pending`, then ok or declined.

Any other change from outside the dialog goes the same way (`requestProfileChange()`): `herdr-app do kelpie.claude-<profile>--<folder>` too, as any agent can run a command. Messages to agents all go through `sendToClaude()` (config.js): `hc get`'s foreground process must be Claude (or the demo's stand-in), as any terminal can print the escape that makes Herdr list it as an agent, and a message typed into a shell would run. `hc()` resolves a refused send (blocked, still settling, gone) with its exit code rather than rejecting, so a non-zero `hc send` throws, in plain words (`sendError()`); the text goes after `--`. hc holds a send while it thinks the person has text typed there and not sent: text keys since the last Enter, not what the screen shows (tried on hc 0.1.20: Backspace and Ctrl+U clear it, but a Claude prompt cleared with Esc Esc or a menu answered with a key still counts), until 60 s after their last key, any key or mouse movement over the pane starting those 60 s again; and Herdr stops a mod's `hc()` after 30 s, which cancels that send (it never lands later).

So `sendToClaude()` tries again, `HOLD_TRIES` (6) in all, about 3 minutes, checking the foreground program before each (no copy can double, as a cancelled send never lands), then fails in plain words (`HELD`); its `onHeld` is called once if the send hasn't gone 5 s in, and every caller then says so with what lets it go (`heldWords()`: click in it and press Ctrl+U, short enough for the note's line and a toast, why in the note's tooltip; the story's note and a toast, `held()` in stories.js; Kelpie never presses a key there itself, which could wipe a real draft). One send at a time to a terminal: another while one waits is refused in plain words (shared `kelpie.sending` by address, `{at, until}`, bounded so a reload mid-send can't lock it), as earlier picks used to pile up (KELPIE-120).

No tool or folder name is in code. A space opened by New space belongs to the profile it was opened from (`kelpie.space.profile`, pruned as spaces close); any other belongs to the deepest profile whose folder holds the folder it began in (`space.folder`); only when that's in no profile does its live folder count, so an agent's `cd` never moves a story's space to another profile. Old per-space setups (`kelpie.spaces`) became profiles on first read. Switching profiles goes back to where that profile was last seen (`kelpie.profile.last`, recorded by `keepProfileOnClose()`: its space, or `null` when it was picked beside another profile's; `switchProfile()` in config.js), and keeps its preview (`syncTracking()` clears a preview only on a space change within one profile).

The sidebar shows the shown space's profile; one picked in the menu (`kelpie.profile.chosen`, with the space shown then) counts only while that space is shown, and when the shown space closes the profile it was in stays (`keepProfileOnClose()`). That tracking (and the closed story's preview, the panel per profile, the skin's hour) runs in one shown copy, `track()` in main.js: the footer, or while `cmd-b` hides the sidebar (`side`; a button in its profile row, and one at the start of the tab bar while hidden; the top row then leaves room for the window buttons) the shown tab bar (`toolbar-start` has props `slot: "start"`). Hidden copies don't redraw and would miss a close; a copy taking over first records what's shown (`syncTracking(true)`, `syncPanel(true)`).

Which copy leads is shared `kelpie.tracker` (`footer`, `toolbar` or `toolbarstart`), not a module flag: with one shared context the copies not leading cleared that flag on every draw, so the footer started over each time and never saved the web panel per profile nor noticed a story's space closing. `herdr-app do kelpie.profile-<id>` picks a profile and `kelpie.preview-<KEY>` shows a story of the shown profile, from outside (scripts, checking a view). A profile picked beside another profile's space shows its own empty screen, not that space's terminals. No project, board, org, site or path is written in code

## Shareability

Shareability: Herdr doesn't tell a mod its name, so `MOD = "kelpie"` in ui.js is the one place it's written (overlays, built `<mod>.<command>` names, `modFile()` script paths); keys.json and layouts name it too. Jira is Jira Cloud only, and enforced: `parseBoard()` and jira.sh take only `https://<name>.atlassian.net` (the token goes there; a demo profile's board may be any address), and jira.sh refuses an email or token holding a quote, backslash or line break (they go into curl's config, where one would add options). A Keychain item's name is one line (`buildProfile()`), and the Board page's store command (`storeCommand()` in setup.js) isn't offered for one that isn't, as a line break would start a `security -i` command of its own.

Sign-in: the profile's optional token command (`jira.tokenCommand`, a shell command printing the API token, e.g. `op read …`, `pass …`, `secret-tool lookup …`; then `jira.email` is saved beside it) replaces the Keychain item; jira.sh gets it as `--token-command`/`--email` and keeps the token in pipes. Off macOS the dialog shows only the token command. Kanban boards (no sprints: the sprint call fails and `/board/<id>` says `kanban`, or `simple`: a team-managed board with sprints off; a `scrum` one keeps the sprint call's error; the profile dialog's Check names the kind in words, `BOARD_TYPES` in setup.js): `activeSprints()`/`boardScope()` in sprint.js use the board's filter and sub-filter, minus work done more than 14 days ago, with the board as the one "sprint". `platform.js` (original in `kelpie`, copied into `kelpie-artifacts`; ui.js re-exports it) holds what differs per system: `openExternal` (open/xdg-open/explorer, a toast when it fails), `reveal`/`revealLabel` (Linux opens the folder), `fullName`, `CLAUDE_TMP` (/private/tmp or /tmp `claude-<uid>`), `STAT_MTIME` (BSD/GNU stat); scripts that may run on another machine ask `uname` there. `claude-statusline.sh [name]` names the account (else from `CLAUDE_CONFIG_DIR`, else Claude)
