# The visual kit

Buttons, marks, agent states, magic, icons, dialogs and spacing. Use these rather than inventing new pieces (`.claude/rules/product.md`).

## Visual kit

Visual kit (ui.js): every button is `primaryButton` (filled accent, the one main action) or `textButton` (quiet); one that can't be taken back is `carefulButton()` in stories.js: its first click arms it ("Confirm …") for `ARMED_FOR` (5 s, a timer disarms it and redraws) and only for what was shown then (`this.shownKey`, set by `prepare()`: every header has the same ids, so another story shown would have inherited it); CONTROL high, radius 7, SMALL text, never resized at call sites (the one other size is `ROW_CONTROL`, the story list's row actions); Jira lozenges are `chip`s (kept as words: they're menus). States are marks, not words: `mark(t, state, size)` (a spinner while an agent works, a slow pulse while one waits for you, still icons for the rest: PR states `pr-changes`/`pr-failing`/`pr-approved`/`pr-running`/`pr-review`/`pr-draft`/`pr-merged` from `prState()` in ui.js (imported in stories.js as `prLook`), changes requested first (amber; a story's state `changes`, ranked above failing checks in `need()` and counted apart in the summary), then failing checks (the red x, approved or not), then an approval: `pr-approved`, the green circle even while checks run (ready to merge stories too, `ready`), its checks in its words; changes requested is an amber speech bubble (the theme's `working`), not red; the merge icon is for merged PRs, in the theme's calm blue (`t.ansi4`, a colour no other state uses) with an outlined check in a circle at its top right (`git-merged`, our own icon; a merged PR's name dim in the story), and the Merge menu; `paused`, `idle`…), `countBadge()` (a mark and a count) and `progressBar()` (a story row's counts only your subtasks, `mine`, by their `stage` from `build()`: past the handover column or done green (what its n/m counts), in it blue, in progress amber, blocked (a status named so) red, to do grey; none when none is yours; a story's summary, `progress()`, counts all its subtasks by the same stages, in the need line, the story picker, the Done row's tooltip and the bar's "All:" line: "in <the handover column's name>", past it, in review only before it, "built" for both on a board worked alone, KELPIE-221), each saying its words in a tooltip.

A story row's second line is its key and `storyBadges()` (agents; its open PRs as one mark, picked in the PR states' order above), then its tags at the line's end; its subtasks of yours are a thin line under it, a segment each by stage (`subsLine()`, its words the tooltip; the Done group's rows keep `progressBar()`); its actions (Merge, Request approval, Move to Done, the broom; two can show at once) are compact (`ROW_CONTROL`, 22: the kit's one smaller control, `iconButton()`'s `box`, for dense list rows only) and centred on the title line, which has a set height (`ROW_TITLE`, 20), laid over the row (`rowActions()`, from `ACTIONS_TOP`, 6): by the numbers they end at 28, above the key line's tags (28.5), 6 in from the row's top, with nothing painted behind them, and the title stops short of them (its right margin, one ROW_CONTROL per button); a row is as high with them as without, and the labels and the line keep the row's width; its need sentence the row's tooltip; the list's summary is count badges; PR rows lead with their state's mark (reviews with the author's avatar); "Working on" rows are one line, a space's working/waiting agents counted at its right.

An agent's state has one mark wherever it shows (#101): `agentMark(t, status, {where})` in ui.js, used by the tab bar's slot, a split pane's header, the sidebar's agent rows (Working on, the Desk) and a subtask's slot, with its words from `agentWords()` (`AGENT_WORDS`): needs you (a slow pulse), waiting on you (`asks`: ended its turn waiting on the person, #252, an amber question in a ring, still), working (a spinner), done (finished while you weren't looking: a check), idle (a ring), paused (its session kept), unknown (a Claude that hasn't reported yet: a faint dot, never idle's ring); only working and needs you move. A skin restyles a state through `statusMark` (`where` `tab`, `pane`, `side-tab`, `sub`), the same in all four places, and may not drop or merge one (`tests/js/agent-marks.test.mjs`).

A skin's `statusMark` also wins for the story row's leading mark (Quiet Pages keeps only its safelight for needs you, else Kelpie's marks, for agents and stories alike). Magic is Kelpie's mark for anything Claude does for the person (What next?, Claude's picks, Next's pointer, Let me configure it for you, Ask Claude), the same everywhere so it's learnt once: the sparkles icon (`own("sparkles")`) in the accent, still where nothing happens (Ask Claude's button and the Ask line), breathing slowly while idle and inviting (`sparkle()`), turning with two bubbles while Claude brews (`brewMark()`, with `brewWords()`); an accent tint or edge on what it offers or points at (Claude's picks' box, the pointer's box, the Ask line, the file whose Ask Claude the Ask line points at, lit); a glint running along a border, never across content (`borderGlint()`, for a few seconds to catch the eye, or while Claude works); a halo breathing behind the one button to press (`story-pointed`).

Nothing moves unless Claude is doing something, no bands over content, no fast blinking; a new feature that's Claude's uses these, not marks of its own. No small square marks anywhere (they read as a broken glyph): dots, rings and icons; GitHub's five change squares in the diff header are the one exception; "nothing here" text is `empty()` (dim, SMALL; `fill` centres it in a view); dialogs pad and space by `DIALOG` (16 inset, 8 within a part, 16 between). Footer CPU/Mem are neutral text, red only at the load's `full` (CPU 85, memory 92)

## Icons

Icons: routine actions are 28px icon buttons (`iconButton()` in ui.js: dim, hover/selected fill, a tooltip always, with the key when there is one): the tab bar's side panels (Files, Changes, Artifacts, Web as a globe; the open one selected), +, and the header and diff icons above. Main actions, Pause, view tabs and anything that starts typing stay words. Herdr's own icons are `chrome(name)` (`mods/workspace-chrome`); the Lucide ones it lacks (ISC, `mods/kelpie/icons/`) are `own(name)`. Herdr draws no SVG through a symlinked mod folder (tested), so `own()` reads `art/kelpie/icons`, outside the repo: the sidebar/footer copy copies missing or changed icons there on each start (`install.sh` does the same by hand). `kelpie-artifacts` keeps its own word buttons
