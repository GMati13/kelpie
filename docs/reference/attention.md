# Agents waiting on you

Agents that end a turn waiting on the person, found as their turns end, and how they show.

## Agents waiting in silence

Agents waiting in silence (`triage.js`, #251, part of #249): most agents end a turn with a question, a choice, a plan to approve or work to check and then wait, unflagged (Herdr's `blocked` is only an interactive prompt). So when an agent's turn ends (working to done or idle; or anything to `done`, finished and unseen, as a turn shorter than the time between two of the tracking copy's renders is seen only as idle to done; one first seen `done` after a reload too, unless it already has an entry), the copy that follows what's shown (`noteTurns()`, from main.js `track()` after `syncTracking()`) reads the last message it wrote: `claudeSession()`, then `last-turn.py` where the agent runs (the transcript's end only, in blocks from 64 KB up to 4 MB back; only `~/.claude*` folders of the home folder, ids of letters, digits and dashes, never through a link; the text Claude wrote after its last tool call, its last 2000 characters, its id and time, and when the person's message that began the turn was; a turn ending on a tool has none).

It decides by Kelpie's own rules first (`triageByRules()`: the last paragraph's last sentence a question, kind `plan` when it's about a plan to approve, `choice` when it offers ways, else `question`, its line that sentence), and only when they can't tell asks a small model (`askModel()`): `claude -p` on the profile's Claude account (`claudeArgv()`, `KELPIE_PROFILE`/`KELPIE_STORY` cleared), `--model` the profile's `attention.model` (`TRIAGE_MODEL`, a model's alias or name only, as it goes into the argv; default `haiku`), `--tools ""`, `--strict-mcp-config`, `--permission-mode plan`, `--no-session-persistence`, `--output-format json`, `--json-schema` (`SCHEMA`: state waiting, ready or none, kind, line), run in Herdr's own folder (`appHome()`, so no project's CLAUDE.md or settings come along), 60 s at most; its task on stdin (`feedClaude()`): `prompts.triage` (`ASK_PROMPTS` `triage`, the dialog's Messages "Agents waiting on you" group, `{message}` the message fenced) then `OTHERS`.

Its answer is checked (`cleanAnswer()`: a known state and kind) and its line cleaned and cut to 120 (`cleanLine()`); it's only shown to the person, nothing acts on it. At most 2 run at once, one per agent (a turn ending while that agent's last is still read waits for it). Kept in shared `kelpie.waiting` (`WAITING`) by profile, then agent address: `{turn, at, state, kind, line, how: rules|claude, tab}`, `none` kept too so a reload doesn't ask again, written only on a change; an entry goes once its agent works again or turns blocked (it then needs the person now), its terminal is gone, or after a day, and a deleted profile's go with `pruneShared()` (`byProfile()`). Skipped: a profile with `attention.triage` false ("Find agents waiting on you" on the dialog's Agents page, on by default), an agent in no profile's space, a session on another Claude account than its profile's (#254), a turn already read (its message's id), and a turn in which the agent asked through Next itself (an `ASKS` entry of its terminal since the turn began): its own ask stands. `waitingIn()` gives the views what waits.

Shown (#252): an agent waiting on you is Kelpie's own agent state `asks` (`agentStatus()` in attention.js: its entry `waiting`, not set aside, while it rests; `waitsOnYou()`), drawn by `agentMark()` as an amber question in a ring (`circle-help`, still; amber is the theme's yellow, `waitColor()` in ui.js, never `working`, which Quiet Pages makes its coral needs-you colour), its words "waiting on you", in every place an agent's mark shows (the tab bar's slot from its tab's agent, a pane's header from its pane's, the sidebar's agent rows, a subtask's slot); its story's need ranks `WAITING_RANK` (0.5: after an agent blocked, before changes requested, `waitingOf()`, the longest waiting), its state `asks`, its row led by that mark with the question on its key line in amber in the tags' room (`waits-<KEY>`), and the list's summary counts it (`count-asks`).

The demo answers from its fixture (a tab's `turn` `{last, triage}`, `demoLastTurn()`/`demoTriage()`, no Claude): ACME-152's agent ends asking whether to add a CI secret (the rules), ACME-127's with a fix to try (the model's canned answer).
