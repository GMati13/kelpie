# Security

Kelpie runs commands, holds a Jira sign-in and starts Claude agents on a person's machine, and reads text written by strangers (pull requests, Jira tickets). Every change is checked against these rules, and every protection here has a test that fails when it's removed (`testing.md`).

## What can't be trusted

- Jira and Linear: issue keys, summaries, descriptions, statuses (anyone on the board writes them).
- GitHub: pull request titles, bodies, authors, branch and repo names, file paths, diffs, and the code of a pull request (anyone can open one and request a review).
- Claude session titles and prompts, file names in screenshot folders, web pages in the Web panel.
- Profile settings written by an agent (`kelpie.apply-profile`): an agent can be misled by what it read.
- Anything a terminal prints: a program can print the escape that makes Herdr list it as an agent.

## Rules

**Commands.** Never build shell code out of a value. A `sh -c` script takes values as `"$1"`, `"$2"`…, quoted. Prefer `exec(program, [args])` without a shell. A value that could start with `-` goes after `--` or is validated. Check a ticket key against `^[A-Z][A-Z0-9_]*-\d+$` before it goes into a command or a path.

**The Jira sign-in.** The token never appears in a command's arguments, an environment variable, a file, a log, a notification, shared state or text sent to an agent. It goes to curl on stdin (`jira.sh`). Only `https://<name>.atlassian.net` gets it (`parseBoard()`, `jira.sh`). An email or token with a quote, backslash or line break is refused. Agents never handle secrets and never run a token command. A Linear API key is kept the same way (`linear.sh`): curl's stdin only, sent to `https://api.linear.app/graphql` alone, refused with a quote, backslash or line break.

**Accounts and tokens (GitHub's too).** Anything that touches an account, a sign-in or a token is held to the Jira sign-in's rules. A GitHub token is asked for by the account's name (`gh auth token --user`) and goes only into the one gh run's environment (and so to what gh itself starts), never into an argument, a file, output or shared state, and never to a host it isn't for: GitHub's other hosts that take `GH_TOKEN` (`*.ghe.com`, `github.localhost`) get none. An account inherited from the environment never stands in for the one Kelpie chose: where none is chosen, it's cleared. A script that waits on the person's own shell kills its whole process group when its time is up. A script that holds a token turns tracing off first (`set +xv`: bash, which is macOS's sh, takes xtrace from an exported `SHELLOPTS`), and passes the token to no command, only assigning it. Account names, Keychain items and emails are checked whole: a `case` pattern or an anchored JS regex, never `grep`, which checks each line on its own. A command Kelpie gives the person to copy holds no value that isn't checked. A folder put into `PATH` is absolute, with no colon. Each of these has a test watched failing.

**Agents changing profiles.** Each section takes only its own keys (`SECTION_KEYS` in config.js), so a secret can't slip in under a name `SECRET` doesn't catch; a new setting joins its section's list. What can run a command, steer agents or move the sign-in (`CONFIRM_KEYS` in config.js) waits for the person's click in Kelpie, through a dialog button, never a command an agent could run itself. A new setting of that kind joins `CONFIRM_KEYS`. The same holds for a run that writes to the board or GitHub, or starts agents (Move to Done, Close, Run all): only its dialog's button asks for it, by writing a one-time run request (`askRun()`, shared `kelpie.run.asks`) that no command or plugin request writes, and the copy following what's shown runs it once, its arguments checked again (`takeRuns()`).

**The account boundary.** Profiles may run on different Claude accounts so that one account's work stays away from the other's (#254). A Claude asking through the plugin sees and acts on only its own profile's work: a request's profile is the asking agent's (`whoAsks()` in boundary.js: its terminal's space first, then `KELPIE_PROFILE`, on that profile's own Claude account), never another's by default, never every profile, never the one shown on screen. Kelpie may combine profiles in what it shows the person, never in what it hands a Claude: anything cross-profile an AI feature needs is done per profile, on that profile's account, and merged by Kelpie. Crossing is never silent: only the person turns it on, a pair of profiles at a time in the profile dialog (`kelpie.share`, which no agent's request or command writes), it reaches agents only, and every agent it reaches comes marked so the Claude says so. A refusal reads as "not there", naming nothing kept back. A new request handler goes through `whoAsks()`/`allowedFor()`, with a test that a Claude of another profile gets nothing.

**Messages to agents.** Only through `sendToClaude()`, which checks the terminal's real foreground process. Never `hc(["send", …])` directly.

**Prompts.** A message Kelpie sends Claude carries only values Kelpie checked itself, and the purpose (KELPIE-302): a ticket key by the key pattern (`checkedKey()`), a pull request's page rebuilt from its checked owner, repo and number (`pullParts()`), a ticket's page built from checked parts (`ticketLink()` in board.js: the board's site and the key, a Project's repo and number, Linear's workspace and key), never a link as the load gave it, a folder Kelpie made (`checkedPath()`), Kelpie's own words for a state. Never a title, description, comment, author or assignee name, status or column name, label, branch, a pull request's file path that isn't plain characters, or its code: text in Kelpie's message reads as the person's own, while what Claude fetches itself arrives as a tool's result, which Claude takes as data. The fill functions check every value themselves (a caller can't pass words through), and a profile's prompt still naming an old placeholder (`{summary}`, `{title}`, `{description}`…) gets nothing there. What is the person's or Claude's own may still go: a question typed, a passage the person copied, their own uncommitted code, Claude's own earlier picks and ideas, an agent's last message for the triage model; through `promptValue()` (no control characters), fenced when long, and ending with the `OTHERS` note when it may carry what someone else wrote. Prompts say what to look at or do, never how to reach it: Claude uses its own access (MCP servers, plugins, its tools), with no fallback to what Kelpie loaded; Kelpie's plumbing (`jira.sh`, its `gh` calls, the person's sign-in) is never offered, and no message names a tool. When Claude can't reach something, it says so. `tests/js/checked-values.test.mjs` drives every route with a marker in everything others wrote. With the plugin, a message is a job's skill line (#246): `/kelpie:<skill>` and the same checked values a line each (`dispatchText()` in config.js, the only place one is built), else the job's plain wording; the person's own text (a question, a passage, their lines, Claude's picks) goes after a blank line, fenced as before, and a message is never written where it's sent (`tests/js/dispatch.test.mjs`). A skill the person pinned to a job (`skills`, #244) goes into a message only as `kelpie` or a slash name (`SKILL_PIN`), checked when saved and again when the message is built, and pinning one waits for the person's yes, as a prompt does.

**Other people's code.** Never run it. A review agent starts outside the checkout (in the profile's folder) and reviews by reading. No default prompt asks to run, build, install or test a pull request.

**Background agents.** Claude run without a terminal (What next?, and the small model that reads an agent's closing message, `triage.js`) gets its task on stdin, never as an argument (`ps` shows arguments to every user): `feedClaude()` writes it into a private `mktemp -d` folder, which `stdin.sh` opens as Claude's input and removes before Claude starts. It runs read-only: `--permission-mode plan`, editing tools disallowed, whatever the person's default mode is. The triage model gets no tools at all (`--tools ""`) and no MCP servers (`--strict-mcp-config`), the message it reads fenced and followed by the `OTHERS` note, and what it answers is only a cleaned line shown to the person. Plan mode lets through only tools marked read only: in the plugin, only tools that change nothing of the person's work get that mark (`get_profile`, `save_status`, which only reads a saved answer, `get_next`, `get_story`, which only reads what Kelpie loaded, and `suggest_next`, which only changes what Kelpie suggests).

**Files.** Never delete, overwrite or write through a symlink to a file the person owns; installs and copies skip and report what's in the way. Deletions are guarded by an exact, tested path check (`removeDemo()`, `resetBrowser()`). Temp files and folders: `mktemp` / `mktemp -d` (private), never fixed names in `/tmp`. Caches holding prompts or titles are private.

**Destructive actions.** Closing a space, pausing, cleaning up or killing a process asks first when something is working, and refuses what isn't settled (`cleanBlockers()`: not Done, an open pull request, a busy agent; `cleanUp()` checks those again when it runs, and uncommitted work, and for a reassigned story commits not pushed). Match processes by an exact, tested pattern; never kill what Kelpie didn't start.

## When you change something here

- Adding an `exec`/`hc`/`run` call, a prompt, a profile setting, a file operation or a process kill: check it against these rules and add or extend the tests.
- Found a weakness? Say so to the person before working around it, and fix it with a test.
- Security-sensitive changes are summarised in the commit body.

## Known gaps

Where the code doesn't meet these rules yet (fix them with tests, then remove the line):

- The account boundary holds against a misled Claude, not a determined one: a request file can be written by any program on the machine (naming another terminal or profile), a Claude with file access can read Herdr's `shared.json` and another account's `~/.claude*` folders itself, and Claude's own messaging between sessions lists every local session without asking Kelpie. The README's "Several accounts" gives permission rules for the person's own setup.
- Add to chat (`pasteToChat()`, `mods/kelpie-artifacts/main.js`) pastes a file path, and the note typed with it, into an agent's terminal with `terminal.paste`, without `sendToClaude()`'s check that the terminal really runs Claude. It presses no Enter, and the note is one line with no control characters (`cleanNote()`), so nothing runs by itself.
