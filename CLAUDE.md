# Kelpie

Herdr layouts built around profiles and stories (Jira sprint, pull requests, Claude agents). How to work on it (development, security, testing, product rules) is in `.claude/rules/`, which Claude Code loads on its own; this file is the reference for how each part works. Open source, MIT (`LICENSE`); bundled fonts and icons keep their own licences beside them (OFL, ISC): anything third-party added needs its licence file and an MIT-compatible licence.

## First: universal, not personal

This is a standalone product meant to be shared: anyone installs it and sets it up from the profile dialog. It knows nothing about one person's setup.
- No personal preferences, accounts, paths, projects, boards, orgs, company tools or shell setup in code, docs, layouts, keys or `.claude/` here. Anything that differs per person is a profile setting (or Herdr's own settings) with a generic default, or a convention that degrades gracefully (a folder named after the ticket key)
- A user's own setup lives in their dotfiles, which reuse this repo and put their config on top: their Herdr `keys.json` and settings, Claude Code status line wiring, shell functions, personal permissions (`.claude/settings.local.json`, git-ignored). Notes about one person's machine go there, not here
- Flag macOS-only or other assumptions where they matter (Keychain sign-in, `~/.claude*` folders)
- Every prompt, message and guide Kelpie gives Claude says what to look at or do, never how to reach it: Claude works through its own setup (its MCP servers, plugins, tools and permissions). Kelpie's own plumbing (`jira.sh`, its `gh` calls, the person's Kelpie sign-in) is never offered as a way around that setup, and a message never names a tool ("using gh"). When Claude can't reach something, it says so and asks; that's how it's meant to work, not something to work around. Checking Kelpie's own sign-in is the profile dialog's Check button, not an agent running Kelpie's scripts

## Commit Format

`[scope] description`, scopes: `kelpie`, `skins`, `artifacts`, `docs`, `tests`. Start with a verb (`add`, `update`, `fix`, `remove`), lowercase, concise.

## Install

- `./install.sh` links layouts, themes and mods into `~/.config/herdr-app` (`HERDR_APP_HOME` overrides), then copies what Herdr won't read through a link: the layouts' previews (`layouts/Kelpie*.svg`, the settings' layout picker, copied over each time), the icons (`mods/kelpie/icons/install.sh`) and each skin's art and fonts (`mods/kelpie/skins/copy-art.sh`, the same script the footer runs on each start), so the first start already has the skin's fonts. It replaces only its own links: each run removes its links into the repo and makes them again (so a renamed file leaves no old name; macOS ignores case), and removes broken `[Kk]elpie*` links of an old clone; a real file or folder in the way is left alone, and the run ends by naming it and exits 1. The previews are drawn like Herdr's own: a few bold shapes, as they show about 108px wide. The README's keys step merges `keys.json` with `jq -s '.[0] * .[1]'`, written back with `cat` so a stowed (symlinked) keys.json stays a link
- Herdr won't load images or SVGs through symlinks, and hot reload can't see through them: the footer copies icons and skin art to `~/.config/herdr-app/art/kelpie/` on each start (and skin fonts to `fonts/`, loaded on Herdr's next start)
- Key sections in `keys.json` go into Herdr's own `keys.json` (its `global` section, `cmd-shift-s` → `kelpie.web`, too)

## Working routine

- Tests: `./test.sh` before every commit (about 20 s; the hook, once enabled per clone with `git config core.hooksPath scripts`, and CI run it too). The rules for tests are `.claude/rules/testing.md`; the harness (stubs, helpers, snapshots, the end-to-end check) is `tests/README.md`. A mod's internals may be exported for a test (the `export` keyword only); a shell script a test must run lives in its own file under `mods/kelpie/` (like `skins/copy-art.sh`)
- After editing a mod, re-create its link so hot reload notices: `ln -sfn "$PWD/mods/kelpie" ~/.config/herdr-app/mods/kelpie` from the repo (same for `kelpie-artifacts`), then `herdr-app check mods/kelpie` and `herdr-app status` (its errors list). Pointing the link at another folder (a git worktree, say) isn't noticed until a file's content changes there: touching isn't enough, so add a line to a file and take it out again
- A layout file edit often isn't noticed while that layout is shown, even relinked: `herdr-app do layout.switch '{"name":"<another Kelpie layout>"}'` and back reloads it, but closes open Herdr windows (the settings window, say), so tell the user first. `layout.resize`/`layout.show` act live
- Look before claiming: `node --check --input-type=module < file.js` for syntax, then `herdr-app shot <scratchpad>/x.png` and crop (PIL). For a state hard to reach (a near-limit footer), change the threshold temporarily, shoot, restore, and grep that the restore took
- Driving the UI from outside (`herdr-app do kelpie.profile-<id>`, `kelpie.preview-<KEY>`, `pane.split`…): put the screen back as it was afterwards (profile, panel, sidebar width). `pane.split` once came out doubled: check `herdr-app ls` and close only the panes you made
- Mods have no readable console: debug with a temporary `setShared("kelpie.debug.<role>", {...})`, written only on change (a write per render can loop), and read `~/.config/herdr-app/shared.json`. Herdr owns that file, stray keys can't be deleted by hand, so keep debug names obvious
- `!`-prefixed commands get no TTY: anything interactive (`claude /login`) runs in a real Herdr terminal
- `.claude/settings.json` is the shared permission list (Herdr's, git's and gh's reading commands, though `gh api` is allowed whole, writes too: a known gap in `.claude/rules/security.md`; `hc kill`/`hc rm` always ask); personal permissions go in `.claude/settings.local.json` (git-ignored)

## Herdr notes

- The web panel runs behind `mods/kelpie/kittyfix.py` (it never stops on bad input: a chunked image given up or never finished is dropped after `CUR_FOR`, which used to hold back all output and froze the browser; an unterminated command past `HOLD_MAX` passes through; a parse error passes the bytes on; a command split across reads, even between its terminator's ESC and backslash, is held from its own start, as taking that ESC for a new sequence once broke a frame and froze the picture; and it never blocks: writes go through queues on non-blocking descriptors and Herdr's input is always read, as a blocking write to Herdr once deadlocked both and froze the browser until it was killed; when Herdr is slow, the browser's output waits unread past `OUT_MAX`; text split across reads is joined, so the cursor move placing an image is always found; a held command isn't rescanned while a read has no ESC; terminal-browser draws its first frames before it knows the cell size (16x34 px cells in Herdr's 10x26: a page wider than the panel, whose pieces made the artifacts) and takes the real one only on a resize, and Herdr can answer its question late (~15 s after a restart, still working through the old browser's frames): the proxy answers it at once from the size Herdr last gave (`Cells`, kept in `~/.cache/kelpie/kittyfix-cell`), drops Herdr's same answer when it comes, and when there's none yet or Herdr's differs (a zoom) gives it the pixel size Herdr leaves at 0 and a one-column resize put back after `NUDGE_FOR`, `child_size()`; every image goes out under a fresh id (`FRESH`): an id sent again with a new picture showed its old one for a moment, on top (old video frames flicking in), and the image it replaces, or one the browser deletes, goes at the next frame's end or after `RETIRE_FOR`, once its successor is drawn; while logging (`--log`), each frame is followed by a numbered kitty query whose answer times how far behind Herdr is, with how long the browser took to write the frame and paused before it, `Probes`: during video Herdr kept up within 0.11 s and the browser wrote a 1 MB frame in 0.04 s, then paused ~0.15 s, its own capture rate, about 5 fps whatever `render.fps` says), a PTY proxy fixing Herdr's kitty graphics bugs: Herdr ignores placement `X=`/`Y=` offsets and draws columns 10.083px apart while reporting 10px (zoom 1.2), so terminal-browser's patches land off (stale tiles); and a delete before the new image makes Full frames blink. The proxy pads images into place from column 1 and drops or defers deletes inside each synchronized block. It needs `terminal-browser config set render.presenter patched` once per machine (setting lives outside the repo). `--log FILE` prints counts. Resizing still lags (each size change is a full frame). Don't stream frames into a mod's `image()`: Herdr never frees them (leaked ~160 GB)
- Claude limits come from Claude Code's status line: each Claude config's `settings.json` set to run `mods/kelpie/claude-statusline.sh` (the user's own setup, see README), which saves each session's data (with `config`, its `CLAUDE_CONFIG_DIR`, null when unset) to `~/.cache/kelpie/limits/`, kept 7 days, and prints nothing

- Host reads cost what they hold: `spaces()`, `agents()`, `panes()` and `shared(key)` convert their whole value into the mod engine on every call, and herdr-core lists every space, pane and agent of every Herdr window (a day of story agents is dozens). So a render reads each list once and works from that, never once per space or agent: `spaceProfiles()` in config.js gives each space's profile from one read of each (`profileOf()` for one space, `spacesOf()`, `profileAgents()` and the profile menu go through it). Re-reading them per space made every Kelpie view grow with the square of what herdr-core held (about 1100 reads per sidebar render with 30 other spaces open), past the time Herdr gives a render, and the demo's sidebar stayed "interrupted" (#104). `tests/js/render-cost.test.mjs` checks each view reads as much with 60 other spaces open as with 30

A profile's `project` section (a GitHub Project: `boardOf()` kind `project`, name GitHub, with the github section's `account`) is the other board; board.js's header is the shape its load gives.
